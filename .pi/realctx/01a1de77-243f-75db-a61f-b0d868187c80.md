`src/orchestrator-prompt.ts` contains agy 1.5.9 native Orchestrator planning/execution semantics; `src/agent-profile.ts` appends them only for Orchestrator models. `tests/fixtures/agy-1.5.9-orchestrator-protocol.json` captures the original phase sections, and tests compare their full rule bodies with explicit adaptations for conditional phase identities, pi instruction references, and behavioral wording in place of excluded native-gate guarantees. Live isolation verified: question → no tools or handoff; action → Carbon→Hydrogen write/read; two injected write failures → `enter_plan_mode`→Carbon review→`exit_plan_mode`→Hydrogen success. Actual pi CLI E2E wrote/read `add.ts` and passed Bun assertions; the native system prompt contains the restored protocol. This is prompt-only restoration, not native hooks, gates, or scheduled review enforcement; the source is a versioned baseline, not dynamically extracted. Earlier tests found explicit `exit_plan_mode` and `enter_plan_mode` tools necessary for handoff with `excludeDefaultComponents: true`; disabling that setting alone did not enable handoff. Isolated live ACP testing showed gemini-pro-orchestrator's planning model received `mcp_pi-bridge_ask_user_question` with the installed question tool's schema and default description, and invoked the bridge handler directly without `exit_plan_mode`. An isolated 51-tool MCP catalog also included the question tool in the model declaration. Thus neither planning mode nor a blanket 50-MCP-tool limit explains a particular session missing it. The question handler in this test was a stub, not the real Pi UI.
